# SmartTrade search and filter audit

The Android/iOS app and the Expo web app under `/app/` share the screens and API client below. Admin uses a separate React app. This audit compares the current controls with their Django endpoints and uses isolated test records for regression coverage.

| Surface | Existing controls and API contract | Finding or change |
| --- | --- | --- |
| Mobile/Web Dealer Catalog Items and estimate picking | `DealerEstimateScreen` sends debounced `search`, `category`, `brand`, and `page` to `/catalogue/items/`. | Search now includes product/variant specifications, active variant SKU and name, published draft source sub-business, and descriptions. Code and name ranking still precede metadata. The existing clear control restores the default list. |
| Mobile/Web Buyer and shared Browse | `CatalogueScreen` sends `search`, `category`, `brand`, and `page` to `/catalogue/products`. Brand choices use the category-scoped `/catalogue/brands` list. | Added server-side `availability=pdf\|stock\|authorized`. All quick-filter counts and pages reflect the whole matching result set. Stock and authorization require an active authenticated account. Clearing text removes the applied search immediately. |
| Mobile/Web nearby dealer directory | `NearbyDealersScreen` sends location/radius, `q`, `brand_id`, `category_id`, and `page` to `/dealers/discover/`, with a product-scoped variant from product details. | Matching now includes branch name, SKU, specifications and sub-business metadata. Added brand/category option pagination, retry controls and a combined filter reset. |
| Mobile/Web product dealer listings | Product-specific lookup sends `product`, `variant`, `pin_code`, `locality`, `district`, and `stock_status` to `/dealers/listings`. | Reviewed the existing PIN → locality → district fallback and stock composition. |
| Mobile/Web Dealer workspace | Own inventory sends `search` and `state` to `/businesses/me/listings`. Authorized product picker sends `brand` and `search` to `/catalogue/products`. Brand declarations send `search` plus repeatable `category`. | Inventory uses the expanded multi-token match. Authorized picking uses the shared product matching. Declarations support multi-token brand/company matching with category filters. |
| Mobile/Web General Items | `q` and `page` on `/businesses/me/general-items/`. | Reviewed existing private, debounced server search by name, code and HSN, including clear and page reset. |
| Mobile/Web Dealer targeted catalogues | Dealer's business type is sent as `business_type` to `/catalogues/`. | Reviewed the existing active-document filter. |
| Mobile/Web Company catalogue and authorizations | `search` on Company product list and dealer picker. Grant history sends `search` and `active`. | Product search now covers the same fields as public Browse and remains company-scoped. Grant history matches tokens across dealer, brand and company. The dealer picker retains its eligible-business and exact-ID behavior. |
| Mobile/Web bills, invoices, offline files, enquiries, orders, support and Staff | Reviewed ledger pagination, existing local-file existence checks, and available workspace navigation. | These screens expose no free-text result filter. Dealer incoming commercial modules remain controlled by their existing feature flag. |
| Admin Catalogue and published items | Moderation sends `search` to staff products. Published items send `search` and `page` to `/catalogue/items/`. | Both share expanded backend matching. Admin published-item count and clear controls retain server pagination. |
| Admin Catalogue Vault | `business_type` and `sub_category` on `/admin/catalogues/`. | Added composable `search` by title, brand and filename, and a page-one reset with independent clear. Public results still include only active documents. |
| Admin Extraction Review and Product Media | Reviewed draft eligibility, selected rows, page range and media-type controls. | These control extraction, approval or asset management. They do not send list search parameters. Product Media is selected from the catalogue. |
| Admin Dealer directory, business review, branch and inventory views | Directory sends `search` and `business_type`; branch review sends `business`; stock/listing review sends `business`, `location`, `state`, `stock_status`, and `search`. | Directory matches normalized mobile input and tokens across firm, owner, GSTIN and location. Inventory search also matches product metadata and supports mixed tokens. Branch and status scope reviewed. |
| Admin Company verification, review requests and Dealer Onboarding | Company queues are scoped to pending verification and open review requests on the server. Dealer Onboarding opens a selected business and its review records. | Reviewed the fixed queue scopes and record selection. These views expose no free-text, city/state, role or date filters. |
| Admin dealer authorizations and audit | Authorization sends `search`, company/brand/business IDs and `active`. Audit has source selection and pagination. Catalogue and dealer audit panels can scope by product, grant or listing. | Authorization text supports mixed tokens. Reviewed existing ID/source scope and audit permissions. No date filter is exposed. |
| Admin Enquiries and Orders | Enquiries uses `state` and `page`. Orders uses `q`, `state`, `invoice_kind`, and `page`. | Stale enquiry responses are aborted. Orders now exposes all result pages, resets pagination on filter changes and ignores stale requests. Order text tokens can match across order, invoice, dealer and branch. |
| Admin Support Inbox | `q` and `page` on `/messages/admin/threads/`. | Mixed tokens match across dealer name, owner, locality or district and normalized phone fragments. Unread total remains inbox-wide. |
| Admin Banners and Media | Banner destination product picker sends `search` and `page` to public catalogue; brand and category pickers use paginated selectors. | Destination search benefits from shared product matching. Banner schedule fields and media inputs are edit controls. |

## Data and verification boundaries

A read-only local database check found zero brand rows, zero active vault documents and zero searchable public or priced products for each of `Ashirvad`, `Skipper` and `Elleys`. The regression suite uses a disposable Ashirvad product and verifies brand, HSN, size, active SKU and combined category/brand filtering. Search does not publish or import records.

Automated API, component and build checks cover the changes. This audit did not validate visual behavior against a signed-in production browser or a physical Android build.
